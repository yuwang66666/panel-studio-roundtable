## 模型选型重跑与自动驾驶

模型选型初次由 Qwen 主持，虽然最终通过 GPT 备用模型生成总结，但 7 次洞察调用全部未通过校验，最终洞察为 0，属于降级交付。改为 GPT 主持的新讨论重新生成阵容和全部发言，得到 7 条洞察及 GPT 总结；#5–#8 从切换演练推进到数据退出、分层路由和合规降级，实际形成连续补充。最终总结明确限定为局部共识，未宣布开源或商业模型普遍更优。两次运行均保留，不能用重跑结果抹去原失败。

自动驾驶案例的 #6–#8 将泛泛的算法优化推进到分车型回归验证、更新包签名、回滚漏洞、维修换件与应急安全边界。#9 提出的“跨车型标准化测试平台”并非前文已经明确提出的方案，却用“很好的想法”承接，存在回应归属不够准确的问题；正文原样保留，不改写成更理想的对话。

## 验收结论如何理解

真实 API 闭环与输出质量是两个检查层次。`source=model` 证明系统保存了通过当前格式校验的模型总结；`insightsThrough` 证明提炼任务读取到了该消息游标，不证明最后每个观点都被洞察逐项概括。保留这些边界，才能避免把“有结果”误写为“语义完全正确”。

本批没有重新执行浏览器 E2E，也没有将 Claude 的最小连接测试扩大为圆桌业务通过。后续重点是更细粒度的共识支持核验、主持人追问准确性，以及 Claude 和默认 16 次专家发言配置的真实覆盖。
