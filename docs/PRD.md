# 产品需求

本地中文多智能体圆桌：创建话题 → 动态阵容 → 模型分配 → 用户确认 → 专家参与与主持 → 实时共识分歧 → 自然语言总结。

硬性要求：前后端分离、SQLite、默认四专家与一主持人、专家基于同一公开历史自主选择参与、1–2 句短发言、动态洞察带证据、并行隔离、实时同步、中文响应式和独立滚动。公开状态、流式正文草稿和正式消息，不公开隐藏推理。

已选默认：2–6 专家、16 次专家发言、主持开场/追问最多 4 次、最近 12 条上下文、每 3 条专家发言更新洞察、3 场并行、全局调用并发 4、连接并发 2。深色三栏演播厅，手机页签。

模型配置需求（2026-11-18 更新）：服务商、协议、地址、模型 ID 和 API Key 提前写入根目录 `.env`，后端启动时加载；网页仅浏览和测试已配置模型、选择默认主持人及每位专家的模型，不再手动添加或编辑连接。支持同一服务商的多个模型；每位专家分别绑定可复用连接，主持人连接默认承担后台任务，执行前冻结连接版本。阵容生成使用创建时选择的主持人模型。

配置同步规则：空白模型/密钥条目不出现在可选列表，部分配置或格式错误在启动时报告变量名；相同配置保留版本，变更产生新版本；从清单移除的连接停用但保留历史版本。环境配置只由后端读取，密钥不会返回前端。修改 `.env` 后重启生效，重启中的运行讨论按既有中断恢复规则处理。

流式需求（2026-11-18 更新）：讨论区在专家与主持人生成过程中展示公开正文，包含开场、追问和总结。草稿与正式消息分离，最终校验成功才提交正式消息，只有正式消息进入上下文和证据。刷新和断线恢复同一草稿，不重复显示；修复重试清空旧文本，终止或重启清除未完成草稿。位于底部时跟随片段，上翻阅读不强制滚动；未读计数按正式发言计算。

专家状态小窗（2026-11-18 更新）：每位参与者有独立状态卡，`idle`显示待机，`preparing`涵盖全员参与判断、并发排队、等待公开首段和输出修复，`speaking`仅在收到非空白公开正文后开始。放弃、无效或未获选的参与者及时恢复待机，提交、失败、取消和重启也须清理状态。关注点只从公开专业标签和当前讨论正式回应目标序号构造，不转发内部`proposedFocus`或供应商隐藏推理。状态随草稿原子保存，SSE和快照恢复一致。前端提供状态文字、图标及稳定角色颜色；只使用一个聚合的`aria-live="polite"`区域播报有意义的状态变化，手机可阅读，遵循减少动态效果设置。

洞察与总结资源配置（2026-11-18 更新）：洞察提炼默认每次尝试180秒、8192输出token，可通过 `INSIGHTS_TIMEOUT_MS` 和 `INSIGHTS_MAX_TOKENS` 设置。总结正文默认每次尝试240秒、8192输出token，可通过 `SUMMARY_TIMEOUT_MS` 和 `SUMMARY_MAX_TOKENS` 设置；普通调用60秒。输出修复沿用对应任务的额度。期限包含等待并发名额，单次期限不等于包含重试与修复的总耗时。超时错误须明确阶段与期限，总结重试复用已经完整覆盖的洞察与已保存发言。

首版不含账号、云部署、联网检索、语音视频、时间轴回放或固定专家库。历史样例明确标识，不模拟真实在线调用。真实 API 验证以用户提供的连接为前提。

总结容错需求（2026-11-18 更新）：对所有讨论统一实现“主持人模型 → 本场其他冻结模型 → 本地整理摘要”。用户已明确选择在所有模型不可用时仍提供有来源标识的本地摘要。最终洞察失败不能阻止基于全部正式发言的总结，必须分别记录总结覆盖范围与洞察实际覆盖范围，不能伪造新共识或抬高洞察覆盖序号。模型总结请求默认最多4次，收尾总期限默认6分钟；耗尽后本地整理不再发模型请求。专家阶段持续模型故障自动收尾；已进入收尾的任务重启后保留尝试额度自动恢复，原讨论轮次不自动续跑。取消、过期结果和存储失败不得被伪装为完成。

总结正文要求（2026-11-18 更新）：最终总结和总结草稿只显示自然语言，禁止JSON原文、代码围栏和隐藏推理字段。外层模型响应继续遵守严格JSON协议，正文独立校验；有限白名单允许剥离单字段`content`或`summary`及JSON字符串包装，其他结构进入有限修复、备用模型或本地整理，不能任意拼接对象字段冒充总结。流式遇到未闭合包装或模糊结构片段时暂缓展示，安全的普通正文保持逐段显示；最终保存前再次检查完整正文。本地整理中无法安全摘录的结构化记录以可追溯提示替代。存量历史坏格式仅在阅读层依据该总结之前的正式发言重建本地摘要，明确说明来源和原记录未修改，保留证据跳转，不修改历史模型元数据。

交付过程采用逐项验收：见 tasks.md 与 verification.md，失败检查修复后再继续。
